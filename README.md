# Invora Reader — قراءة فواتير الموردين الممسوحة

## الحجر الأساس: حلقة «اقرأ ← راجع ← اتعلّم»
```
 scans/*.pdf ──read──▶ out/upload.csv  (status = auto | review)
                          │
                          ├─ auto  ─────────────▶ سكريبت الرفع على سوفتك  (docs/UPLOAD_SCHEMA.md)
                          │
                          └─ review ─ review ─▶ review.xlsx  (صورة السطر + الأعمدة + الكود المقترح)
                                                    │  تصحّح وتعلّم ✔/✘
                                                    ▼
                                      learn ─▶ learned.json ─▶ القراءة الجاية أدق (--learned)
```
كل تصحيح بتعمله بيتحوّل لقاعدة بتتطبق تلقائيًا، وعينة «تلقائي» جوه الملف بتقيس الدقة الحقيقية. التفاصيل: `docs/MATCHING.md` (طريقة المطابقة)، `docs/UPLOAD_SCHEMA.md` (عقد الداتا).

```bash
python -m invora_reader read scans/*.pdf --master master.xlsx --system export1.htm export2.htm --out out/ [--learned learned.json]
python -m invora_reader review out/invoices.json --pdf-dir scans/ --out review.xlsx      # ملف المراجعة
python -m invora_reader learn review.xlsx --store learned.json                           # اتعلّم من اللي راجعته
```


أداة Python محلية (OCR بـ Tesseract، من غير إنترنت) بتقرأ فواتير الموردين الممسوحة (PDF)، وتطلّع:
الأصناف، الكميات، الأسعار، الخصومات، وتطابق كل صنف مع **ماستر الأصناف** (كود سوفتك)، وتربط الفاتورة بإدخالها
في السيستم للتحقق.

الحالة: **v0.1 — الخطوة الأولى (قراءة الأصناف والخصومات + matching)**. الرفع على سوفتك لسه ما اتعملش.

## التركيب
```bash
pip install -r requirements.txt
# Tesseract + العربي:   Linux: apt install tesseract-ocr tesseract-ocr-ara tesseract-ocr-eng
#                      Windows: installer من UB-Mannheim وتختار Arabic، وتضيفه للـ PATH
```

## التشغيل
```bash
python -m invora_reader read scans/*.pdf \
    --master "data 31-10-2026.xlsx" \
    --system "فواتير شراء.htm" \
    --out out/
```
يطلع `out/upload.csv` (الداتا اللي هتترفع: سطر لكل صنف، `status` = auto/review)، و`out/invoices.json` (كل التفاصيل) و`out/lines.csv` (سطر لكل صنف، فيه أفضل كود مطابق + الكود الفعلي في
السيستم + `top1_matches_system`). `--system` اختياري: من غيره بتتعمل القراءة والـ matching بس.

## التعلّم من المراجعة
اسم الصنف عند المورد أحيانًا بيختلف تمامًا عن اسمه في سوفتك (`HAIR AND NAILS` عند ابن سينا = `BIOTIN` في سوفتك)، وده مش ممكن يتخمّن.
راجع `upload.csv` وصحّح عمود `item_code` للأسطر الغلط، وبعدين:
```bash
python -m invora_reader learn reviewed.csv --store learned.json
python -m invora_reader read scans/*.pdf ... --learned learned.json
```
أي صنف اتأكد مرتين بنفس الكود بيبقى `auto` في المرات الجاية (المفتاح: كود المورد في ابن سينا الجديد، واسم الصنف صوتيًا في غيره).

## قاعدة auto / review
قيست على العينة (الفاتورة نفسها مستبعدة من التاريخ المسبق):
- PharmaOverseas: `score ≥ 90` و`فرق ≥ 15` عن المرشح التاني ← 71% من الأسطر تلقائي، دقة الكود 97.7% (668 سطر).
- ابن سينا (التخطيط الجديد): `score ≥ 95` و`فرق ≥ 15` ← 11 من 27 سطر صح بالكامل، **لكن العينة صغيرة جدًا**. التخطيط القديم كله review.
- **التاريخ المسبق** (الأكواد المشتراة قبل كده من نفس المورد بنفس السعر، من ملف السيستم) بيضيف حتى +30 للـ score. من غير `--system`
  الـ scores أقل، فالحدود دي ماتنطبقش.

## القوالب المدعومة
| المورد | الملف | ملاحظات |
|---|---|---|
| PharmaOverseas | «اذن استلام مسعر» | بدون خطوط جدول؛ الصف بيتحدد من عمود نسبة الخصم |
| ابن سينا فارما (قديم، أبريل–أغسطس، التاريخ dd-mm-yyyy) | «Statement Cash» | الصف من عمود نسبة الضريبة؛ أسماء عربي بدون سعر جمهور |
| ابن سينا فارما (جديد، أكتوبر+، التاريخ ISO) | «Statement Cash / Credit» | الصف من كود المورد؛ أسماء إنجليزي + سعر جمهور + هامش |

مورد جديد = ملف `<name>_template.py` جديد بنفس الواجهة `read_page(clean_image) -> {"lines", "totals", "warnings"}`.

## إزاي بتشتغل
1. **prep.py**: تحويل الـ PDF لصور، تصحيح الاتجاه (0/90/180/270)، تصحيح الميل، مسح خطوط الجدول.
2. **القالب**: تحديد الصفوف من عمود نظيف، وقراءة كل خلية لوحدها (أرقام فقط)، وأسماء الأصناف بالعربي.
3. **التحقق الحسابي** (أهم جزء، لأن الأرقام الممسوحة بتتقرا غلط أحيانًا):
   - PharmaOverseas: `الإجمالي = الكمية × (سعر الصيدلي + ضريبة الوحدة)` والضريبة = 14% من سعر الصيدلي،
     والكمية لازم تطلع عدد صحيح. لو الخلية اتقرت غلط بنجرب المصادر التانية (من الضريبة، أو من سعر الجمهور والخصم).
   - ابن سينا: `قبل الضريبة = (الضريبة ÷ 0.14) ÷ ((1−خصم المورد)(1−خصم ابن سينا))` والكمية = ده ÷ السعر.
     والإجماليات: `مجموع الأسعار − خصم المورد − خصم ابن سينا + الضريبة = إجمالي الفاتورة`.
4. **match.py**: الماستر أسماؤه إنجليزي والفاتورة عربي، فالاتنين بيتحولوا لـ«هيكل حروف ساكنة» (`ليبيتور` و`LIPITOR` ← `lbtr`)
   وبتتقارن مع الأرقام اللي في الاسم (التركيز/العدد) وسعر الجمهور (±6%).
5. **link.py**: ربط الفاتورة بإدخال السيستم بالمورد + التاريخ + الإجمالي، وربط الأسطر بالكمية والكود والسعر.
